# Аня + Лёша — сайт с пожеланиями

Аня открывает личную ссылку без пароля, пишет черновик и отправляет весь список один раз. Лёша входит в `/admin`, читает пожелания и скачивает `wishes.txt`. Список хранится в PostgreSQL, а не на временном диске Render. Сайт подходит для телефона и ПК.

## Запуск на Render

1. В [Neon](https://console.neon.tech/) создай проект базы данных. Нажми **Connect** и скопируй **Connection string** вида `postgresql://…`. Копируй только адрес, без `psql` и кавычек, сохраняя параметры TLS в конце. Эту строку не отправляй в чат и не загружай на GitHub.
2. В Render используй **Web Service** (можно ранее созданный `42`), подключённый к этому репозиторию и ветке с изменениями. Static Site не запускает сервер.
3. Выставь настройки:

| Поле | Значение |
| --- | --- |
| Runtime | Node |
| Root Directory | Пустое поле — корень репозитория |
| Build Command | `npm ci --omit=dev` |
| Start Command | `npm start` |
| Health Check Path | `/healthz` |

4. В **Environment** добавь:

| Key | Value |
| --- | --- |
| `DATABASE_URL` | Строка подключения из Neon |
| `ADMIN_PASSWORD` | Твой отдельный пароль, минимум 16 символов |
| `NODE_ENV` | `production` |

5. Сохрани настройки и нажми **Manual Deploy → Deploy latest commit**. Таблицы базы подготовятся автоматически.
6. Открой адрес именно **Web Service**, добавив `/admin`. Введи пароль. Скопируй личную ссылку из кабинета и отправь её Ане целиком, включая `#key=…`.
7. После её отправки нажми **Проверить новые пожелания**, затем **Скачать файлом .txt**. Файл появится в загрузках твоего устройства.

Можно создать Web Service через **New → Blueprint** с файлом `render.yaml`: там уже записаны настройки, останется указать секретные переменные. Пароли в файлы репозитория не вписывай.

Старый Static Site не запускает новый сервер. Пользуйся адресом Web Service. Архив `MySite-GitHub.zip` — прежняя статическая версия, при этом запуске он не используется.

## Как это работает

- Отправить список можно один раз для всего сайта, даже с другого телефона. Пароль или ссылка не сбрасывают уже отправленный список.
- Черновик остаётся в браузере Ани, отправленный список — в базе. На твой ПК файл попадает после нажатия «Скачать».
- Личная ссылка разрешает отправку. Не публикуй её. Обычная ссылка открывает сайт и игры, но не разрешает отправлять пожелания.
- Вход в кабинет действует два часа. После перезапуска сервера нужно войти снова; пожелания и личная ссылка сохраняются.
- Free Web Service Render засыпает при простое, первый заход может занять около минуты. [Ограничения Render](https://render.com/docs/free).
- Диск бесплатного Render временный. Бесплатная Render Postgres истекает через 30 дней; здесь используется отдельный Neon. Проверь условия плана при создании базы, сохраняй скачанный файл как свою копию.
- Чтобы поменять пароль, измени `ADMIN_PASSWORD` в Render и перезапусти сервис. Пароля по умолчанию нет.

## Где менять тексты

`MySite-GitHub/TEXTS.json` — тексты, комплименты и идеи игр. `MySite-GitHub/ADMIN_TEXTS.json` — тексты кабинета. Меняй значения, сохраняя JSON-разметку и названия полей.

## Проверки для разработчика

Node 24, `npm ci`, `npm test`. Тесты запускают изолированный PostgreSQL через PGlite, без доступа к рабочему Neon. Проверяют вход/выход, защиту закрытых данных, ограничения попыток входа, конкурентную однократную отправку, повтор после потери ответа, скачивание и сохранность после пересоздания HTTP-сервера. Для локального HTTP установи `NODE_ENV=development`; на Render оставляй `production`.

После настройки настоящей базы проверь `/healthz`, вход в `/admin` и открытие формы по личной ссылке. Не отправляй пробный список в рабочую базу: это использует единственную отправку Ани. Для полной проверки используй отдельную тестовую базу.
